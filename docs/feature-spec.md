# 기능 명세서

> 기준: `backend-study-cafe-wireframe.html`, 예시 ERD
> 와이어프레임에 없지만 직접 정한 내용은 **(결정)** 으로 표시하고, 이유는 [5. 결정 사항](#5-결정-사항과-제안)에 모았다.

## 1. 개요

- 서비스: 백엔드 스터디원이 과제를 제출하고 서로 피드백을 남기는 스터디 카페
- 사용자 종류

  | 사용자 | 설명 |
  | --- | --- |
  | 비회원 | 가입·로그인 화면만 이용할 수 있다. 그 밖의 화면에서는 가입·로그인 안내 화면을 본다. |
  | 회원 | 로그인한 스터디원. 과제·댓글 조회와 작성, 회원 목록 조회를 할 수 있다. |

- 권한: 과제와 댓글의 수정·삭제는 **작성자 본인**만 할 수 있다.
- 공통 규칙
  - 글자 수는 띄어쓰기를 포함한 **글자 단위**로 센다. (이모지 1개 = 1글자)
  - 텍스트 입력은 **앞뒤 공백을 제거한 뒤** 길이를 검사한다.
  - 화면에서 막는 것과 별개로, 로그인 여부·권한·입력 제약은 **서버에서도 다시 검사**한다. (결정)
  - 탈퇴한 회원이 작성한 과제와 댓글은 남고, 작성자는 **"탈퇴한 회원"** 으로 표시한다.

## 3. 기능 상세 — 회원

### F-01. 스터디 가입

- 설명: 비회원이 정보를 입력해 스터디원으로 가입한다. 가입하면 바로 로그인 상태가 된다.
- 사용할 수 있는 사람: 비회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 이름 | O | 2~30자 |
  | 닉네임 | O | 2~20자, 활동 중인 회원끼리 중복 불가 (대소문자 구분 안 함) |
  | 이메일 | O | 이메일 형식, 최대 100자, 활동 중인 회원끼리 중복 불가. 소문자로 바꿔 저장 |
  | 비밀번호 | O | 8~64자 |
  | 비밀번호 확인 | O | 비밀번호와 일치 |
  | 관심 분야 | X | 최대 50자 |
  | 자기소개 | X | 최대 200자 |
  | 공개 정보 확인 체크 | O | 체크해야 가입 가능 |

- 정상 흐름
  1. 비회원이 상단의 [스터디 가입] 또는 안내 화면의 [스터디 가입하기]를 누른다.
  2. 정보를 입력하고 공개 정보 확인에 체크한 뒤 [가입하고 시작하기]를 누른다.
  3. 회원이 생성되고 바로 로그인 상태가 된다.
  4. 과제 게시판으로 이동하고 "스터디 가입이 완료되었습니다." 알림을 보여 준다.
- 실패·예외 흐름 (위에서부터 순서대로 검사)

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 이름이 2~30자가 아님 | 가입 거절 | "이름은 2~30자로 입력해주세요." |
  | 닉네임이 2~20자가 아님 | 가입 거절 | "닉네임은 2~20자로 입력해주세요." |
  | 이메일 형식이 아님 | 가입 거절 | "이메일 형식이 올바르지 않습니다." (결정) |
  | 이미 사용 중인 이메일 | 가입 거절 | "이미 사용 중인 이메일입니다." |
  | 이미 사용 중인 닉네임 | 가입 거절 | "이미 사용 중인 닉네임입니다." |
  | 비밀번호가 8~64자가 아님 | 가입 거절 | "비밀번호는 8~64자로 입력해주세요." |
  | 비밀번호 확인 불일치 | 가입 거절 (화면에서 검사) | "비밀번호 확인이 일치하지 않습니다." |
  | 이미 로그인한 상태로 가입 화면에 들어옴 | 가입 폼을 보여 주지 않음 | "이미 로그인되어 있습니다. 새 계정 가입은 로그아웃 후 진행해주세요." |

- 비고
  - 이메일 중복과 닉네임 중복은 **오류를 따로 구분**한다. 프론트가 어느 칸을 고칠지 안내할 수 있게 하기 위해서다. (와이어프레임 샘플 글 101번 댓글)
  - 비밀번호는 평문이 아니라 해시(BCrypt)로 저장한다. (결정)
  - 탈퇴한 회원의 이메일·닉네임으로 다시 가입할 수 있다. 이때는 새 회원으로 가입되며 기존 글의 권한은 이어지지 않는다.

### F-02. 로그인

- 설명: 이메일과 비밀번호로 로그인한다.
- 사용할 수 있는 사람: 비회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 이메일 | O | 앞뒤 공백 제거, 대소문자 구분 없이 비교 |
  | 비밀번호 | O | |

- 정상 흐름
  1. 로그인 화면에서 이메일과 비밀번호를 입력하고 [로그인]을 누른다.
  2. 로그인 상태가 되고 과제 게시판으로 이동하며 "로그인했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 없는 이메일, 틀린 비밀번호, 탈퇴한 회원 | 로그인 거절 | "이메일 또는 비밀번호를 확인해주세요." |
  | 이미 로그인한 상태로 로그인 화면에 들어옴 | 폼을 보여 주지 않음 | "이미 로그인되어 있습니다" |

- 비고: 실패 이유(이메일이 없는지, 비밀번호가 틀렸는지)를 **구분하지 않는다**. 구분하면 어떤 이메일이 가입되어 있는지 남이 알아낼 수 있기 때문이다.

### F-03. 로그아웃

- 사용할 수 있는 사람: 회원
- 정상 흐름
  1. 상단의 [로그아웃]을 누른다.
  2. 로그인 상태가 끝나고 과제 게시판(비회원이므로 안내 화면)으로 이동하며 "로그아웃했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 이미 로그아웃된 상태 | 오류 없이 로그아웃 상태 유지 (결정) |

### F-04. 내 정보 조회

- 사용할 수 있는 사람: 회원
- 정상 흐름
  1. 사이드바나 상단의 [내 정보]를 누른다.
  2. 이름, 닉네임, 이메일, 관심 분야, 자기소개, 가입일을 보여 준다. 관심 분야·자기소개가 없으면 "미등록"으로 표시한다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 로그인하지 않음 | 가입·로그인 안내 화면 |

- 비고: 이름과 이메일은 **본인에게만** 보여 준다. 내 정보 수정 기능은 와이어프레임에 없다.

### F-05. 스터디 탈퇴

- 사용할 수 있는 사람: 회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 안내 확인 체크 | O | "탈퇴 후에도 작성한 글과 댓글이 남는다"에 체크 |
  | 확인 문구 | O | 정확히 `탈퇴` |

- 정상 흐름
  1. 내 정보 화면 아래 "스터디 탈퇴"에서 체크하고 `탈퇴`를 입력한 뒤 [스터디 탈퇴]를 누른다.
  2. "정말 탈퇴하시겠어요?" 확인 창에서 [탈퇴 완료]를 누른다.
  3. 회원이 탈퇴 처리되고 로그아웃되며, 과제 게시판으로 이동하고 "탈퇴가 완료되었습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 확인 문구가 `탈퇴`가 아님 | 탈퇴 거절 (화면에서 검사) | "확인 문구 ‘탈퇴’를 정확히 입력해주세요." |
  | 확인 창에서 [취소] | 아무것도 바뀌지 않음 | |

- 탈퇴 후 데이터 처리
  - 회원 행은 지우지 않고 탈퇴 시각을 기록한다. 이름, 닉네임, 이메일, 관심 분야, 자기소개, 비밀번호는 비운다. (결정: ERD 방식)
  - 탈퇴한 회원은 로그인할 수 없고 회원 목록에서 빠진다.
  - 작성한 과제, 첨부파일, 댓글·답글은 남고 작성자는 "탈퇴한 회원"으로 표시된다.
  - 다시 가입해도 기존 글의 수정·삭제 권한은 복구되지 않는다.

### F-06. 회원 목록 조회·검색

- 사용할 수 있는 사람: 회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 검색어 | X | 닉네임 또는 관심 분야에 포함된 글자. 부분 일치, 대소문자 구분 안 함. 비우면 전체 |

- 정상 흐름
  1. 사이드바의 [회원 목록]을 누른다.
  2. **활동 중인 회원만** 가입일 최신순으로 카드 형태로 보여 준다. 위에 "활동 회원 N명"을 표시한다.
  3. 카드에는 닉네임, 관심 분야, 자기소개, 가입일을 보여 주고 내 카드에는 "나" 표시를 붙인다. 관심 분야·자기소개가 없으면 "관심 분야 미등록", "아직 자기소개를 작성하지 않았습니다."로 표시한다.
  4. 검색어를 입력하고 [검색]을 누르면 조건에 맞는 회원만 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 로그인하지 않음 | 가입·로그인 안내 화면 | |
  | 검색 결과 0명 | 빈 목록 (오류 아님) | "검색 결과가 없습니다. 다른 닉네임이나 관심 분야를 입력해주세요." |

- 비고: 이름과 이메일은 회원 목록에 **공개하지 않는다**. 페이지 나누기는 없다.

## 4. 기능 상세 — 과제·댓글

### F-07. 과제 목록 조회

- 설명: 전체 과제를 최신순으로 한 페이지에 10개씩 보여 준다.
- 사용할 수 있는 사람: 회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 페이지 | X | 기본 첫 페이지 |

- 정상 흐름
  1. 사이드바의 [과제 게시판]을 누르거나 로그인 직후 들어온다.
  2. 과제를 **작성일 최신순**으로, 작성일이 같으면 **번호가 큰 순**으로 정렬해 한 페이지에 10개씩 보여 준다.
  3. 한 줄에는 번호, 제목, 작성자 닉네임, 작성일을 보여 준다. 제목 옆에는 댓글 수 `[n]`(삭제된 댓글 제외)과 첨부 수 `첨부 n`을 0이 아닐 때만 표시한다.
  4. 목록 위에 "전체 N개의 과제"를 표시한다.
  5. 아래 페이지 번호로 이동한다. 첫 페이지에서는 `‹`, 마지막 페이지에서는 `›`를 누를 수 없다.
  6. 제목을 누르면 과제 상세(F-10)로 이동한다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 로그인하지 않음 | 가입·로그인 안내 화면 | "스터디원으로 가입하면 과제를 제출하고…" |
  | 과제가 하나도 없음 | 빈 목록 (오류 아님) | "표시할 과제가 없습니다. 검색 조건을 바꾸거나 첫 과제를 제출해보세요." |
  | 없는 페이지 요청 (예: 2페이지까지인데 5페이지) | 빈 목록과 전체 페이지 수를 돌려준다 (결정) | |
  | 페이지 값이 음수이거나 숫자가 아님 | 요청 거절 (결정) | |

- 비고: 정렬에 번호를 보조 기준으로 두는 이유는, 작성일이 같은 과제끼리 순서가 바뀌어 페이지를 넘길 때 같은 글이 두 번 보이거나 빠지는 것을 막기 위해서다. (샘플 글 106번)

### F-08. 과제 검색

- 설명: 검색 범위를 골라 검색어가 포함된 과제만 목록으로 본다.
- 사용할 수 있는 사람: 회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 검색 범위 | X | 제목+내용, 제목, 작성자 중 하나. 기본값 제목+내용 |
  | 검색어 | X | 앞뒤 공백 제거. 비우면 전체 목록 |

- 검색 방식

  | 검색 범위 | 비교 대상 | 비교 방법 |
  | --- | --- | --- |
  | 제목+내용 | 제목, 내용 | 부분 일치, 대소문자 구분 안 함 |
  | 제목 | 제목 | 위와 같음 |
  | 작성자 | 작성자 닉네임 | 위와 같음 |

- 정상 흐름
  1. 검색 범위를 고르고 검색어를 입력한 뒤 [검색]을 누른다.
  2. 결과를 F-07과 같은 형식으로 **1페이지부터** 보여 준다.
  3. 목록 위에 "전체 N개의 과제"와 [검색 초기화]를 보여 준다.
  4. [검색 초기화]를 누르면 검색어를 지우고 전체 목록 1페이지로 돌아간다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 로그인하지 않음 | 가입·로그인 안내 화면 | |
  | 결과 0건 | 빈 목록 (오류 아님) | "표시할 과제가 없습니다. 검색 조건을 바꾸거나 첫 과제를 제출해보세요." |
  | 정해진 세 가지가 아닌 검색 범위 | 검색 거절 (결정) | |

- 비고
  - 사이드바 메뉴로 이동하면 검색 조건이 초기화된다.
  - "내가 제출한 과제"(F-09)에서도 같은 검색을 쓸 수 있고, 이때는 내 과제 안에서만 찾는다.
  - "탈퇴한 회원"으로 작성자 검색을 할지는 [5절](#5-결정-사항과-제안) 참고.

### F-09. 내가 제출한 과제 조회

- 설명: 내가 작성한 과제만 F-07과 같은 형식으로 보여 준다.
- 사용할 수 있는 사람: 회원
- 정상 흐름
  1. 사이드바의 [내가 제출한 과제]를 누른다.
  2. 로그인한 회원이 작성한 과제만 F-07과 같은 정렬·페이지 방식으로 보여 준다.
  3. F-08 검색을 함께 쓸 수 있다.
- 실패·예외 흐름: F-07과 같다. 내 과제가 없으면 빈 목록을 보여 준다.
- 비고: 탈퇴 후 다시 가입하면 새 회원이므로 이전 계정의 과제는 여기에 나오지 않는다.

### F-10. 과제 상세 조회

- 사용할 수 있는 사람: 회원
- 정상 흐름
  1. 목록에서 과제 제목을 누른다.
  2. 제목, 작성자, 작성 일시(시·분까지), 수정한 적이 있으면 "수정됨", 본문(줄바꿈 유지)을 보여 준다.
  3. 첨부파일이 있으면 "첨부파일 n개"와 파일마다 이름, 크기, [다운로드]를 보여 준다.
  4. 아래에 댓글 수(삭제된 댓글 제외)와 댓글·답글 목록, 댓글 입력창을 보여 준다. (F-15~F-18)
  5. 내가 쓴 과제이면 [수정], [삭제] 버튼을 보여 준다. 남의 과제에는 [목록]만 보인다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 로그인하지 않음 | 가입·로그인 안내 화면 | |
  | 없거나 삭제된 과제 | 조회 실패 | "과제를 찾을 수 없습니다. 삭제되었거나 존재하지 않는 과제입니다." |

- 댓글 표시 규칙
  - 최상위 댓글과 답글 모두 **작성일 오래된 순**(같으면 번호 작은 순)으로 보여 준다. 답글은 부모 댓글 바로 아래에 들여 쓴다.
  - 삭제된 댓글에 살아 있는 답글이 있으면 그 자리에 "삭제된 댓글입니다."를 보여 주고, 답글이 없으면 아예 보여 주지 않는다.
  - 내 댓글에는 "내 댓글" 표시와 [수정], [삭제]를 보여 준다. 최상위 댓글에만 [답글]이 있다.

### F-11. 과제 제출

- 설명: 회원이 제목, 내용, 첨부파일을 입력해 과제를 제출한다.
- 사용할 수 있는 사람: 회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 제목 | O | 앞뒤 공백을 제외하고 2~100자 |
  | 내용 | O | 앞뒤 공백을 제외하고 1~10,000자, 일반 텍스트, 줄바꿈 유지 |
  | 첨부파일 | X | 최대 5개, 파일 하나당 10MB 이하, 전체 합계 30MB 이하<br>허용 확장자: pdf, zip, md, txt, png, jpg, jpeg, webp, docx, pptx, json, sql |

- 정상 흐름
  1. 과제 게시판에서 [＋ 과제 제출]을 누른다.
  2. 제목과 내용을 입력한다.
  3. (선택) 파일을 선택하거나 업로드 영역에 끌어다 놓는다. 첨부한 파일은 이름과 크기로 표시되고 개수가 `n/5`로 표시되며, [제거]로 뺄 수 있다.
  4. [과제 제출]을 누른다.
  5. 과제가 저장된다. 작성자는 로그인한 회원, 작성일은 제출 시각이다.
  6. 방금 제출한 과제의 상세 화면으로 이동하고 "과제를 제출했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 로그인하지 않음 | 제출 거절, 가입·로그인 안내 화면 | |
  | 제목이 비었거나 공백 제외 2~100자가 아님 | 제출 거절 | "제목은 앞뒤 공백을 제외하고 2~100자로 입력해주세요." (결정) |
  | 내용이 비었거나 공백만 있거나 10,000자 초과 | 제출 거절 | "내용은 1~10,000자로 입력해주세요." (결정) |
  | 첨부파일이 5개 초과 | 파일 첨부 거절 (글 작성은 계속 가능) | "파일은 기존 파일을 포함해 최대 5개까지 첨부할 수 있습니다." |
  | 허용하지 않는 확장자 | 파일 첨부 거절 | "허용하지 않는 파일 형식이 포함되어 있습니다." |
  | 파일 하나가 10MB 초과 | 파일 첨부 거절 | "파일 하나의 크기는 10 MB 이하여야 합니다." |
  | 전체 합계가 30MB 초과 | 파일 첨부 거절 | "첨부파일 전체 크기는 30 MB 이하여야 합니다." |
  | 작성 중 [취소] | 확인 창 → 확인하면 입력을 버리고 게시판으로 | "저장하지 않은 내용과 파일 변경을 취소할까요?" |

- 비고
  - 화면에서는 파일을 고르는 순간 검사해서 **그 파일만** 거절한다. 한 번에 고른 파일 중 하나라도 걸리면 그때 고른 파일 전체를 거절하며, 검사 순서는 개수 → 확장자 → 파일 하나 크기 → 전체 크기다.
  - 서버는 파일이 과제와 함께 들어오므로 첨부 조건을 어기면 **요청 전체를 거절**한다. (결정)

### F-12. 과제 수정

- 사용할 수 있는 사람: 작성자 본인
- 입력값: F-11과 같다. 추가로 **남길 기존 첨부파일**을 고른다.
- 정상 흐름
  1. 내가 쓴 과제 상세에서 [수정]을 누른다.
  2. 기존 제목, 내용, 첨부파일이 채워진 수정 화면이 열린다. 기존 파일에는 "기존 파일" 표시가 붙는다.
  3. 제목·내용을 고치고, 기존 파일을 [제거]하거나 새 파일을 추가한다. 개수·용량 제한은 **남긴 기존 파일과 새 파일을 합쳐** 검사한다.
  4. [수정 완료]를 누른다.
  5. 변경 내용이 저장되고 수정 일시가 기록된다. 제거한 기존 파일은 이때 실제로 삭제된다.
  6. 과제 상세로 이동해 "수정됨" 표시와 함께 "과제를 수정했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 작성자가 아님 (탈퇴 후 다시 가입한 경우 포함) | 수정 거절 | "수정할 수 없는 과제입니다. 본인이 작성한 과제만 수정할 수 있습니다." |
  | 없거나 삭제된 과제 | 수정 거절 | "수정할 수 없는 과제입니다." |
  | 제목·내용·첨부 조건 위반 | F-11과 같음 | F-11과 같음 |
  | 남길 파일로 이 과제의 첨부가 아닌 파일을 보냄 | 수정 거절 (결정) | |
  | [취소] | 확인 창 → 확인하면 원래 과제 상세로. **기존 파일은 그대로 유지** | "저장하지 않은 내용과 파일 변경을 취소할까요?" |

### F-13. 과제 삭제

- 사용할 수 있는 사람: 작성자 본인
- 정상 흐름
  1. 내가 쓴 과제 상세에서 [삭제]를 누른다.
  2. "과제와 첨부파일, 댓글·답글이 함께 삭제됩니다." 확인 창에서 [과제 삭제]를 누른다.
  3. 과제, 첨부파일(저장된 실제 파일 포함), 댓글·답글이 **완전히 삭제**된다.
  4. 과제 게시판으로 이동하고 "과제를 삭제했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 작성자가 아님 | 삭제 거절 |
  | 없거나 이미 삭제된 과제 | 삭제 거절 |
  | 확인 창에서 [취소] | 아무것도 바뀌지 않음 |

- 비고: 댓글과 달리 과제는 흔적을 남기지 않고 지운다. 삭제 순서는 댓글 → 첨부파일 → 과제다. (외래키 때문)

### F-14. 첨부파일 다운로드

- 사용할 수 있는 사람: 회원
- 정상 흐름: 과제 상세에서 파일의 [다운로드]를 누르면 **원래 파일 이름 그대로** 내려받는다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 로그인하지 않음 | 다운로드 거절 (결정) |
  | 없거나 삭제된 파일 | 다운로드 거절 |

### F-15. 댓글 작성

- 사용할 수 있는 사람: 회원
- 입력값

  | 항목 | 필수 | 제약 |
  | --- | --- | --- |
  | 내용 | O | 앞뒤 공백을 제외하고 1~1,000자 |

- 정상 흐름
  1. 과제 상세 아래 댓글 입력창에 내용을 쓰고 [등록]을 누른다.
  2. 댓글이 목록 맨 아래에 추가되고 "댓글을 등록했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 | 안내 문구 |
  | --- | --- | --- |
  | 로그인하지 않음 | 작성 거절 | |
  | 내용이 비었거나 공백만 있거나 1,000자 초과 | 작성 거절 | "댓글은 공백을 제외한 내용이 있어야 하며 최대 1,000자입니다." |
  | 없거나 삭제된 과제 | 작성 거절 | |

### F-16. 답글 작성

- 사용할 수 있는 사람: 회원
- 입력값: F-15와 같다.
- 정상 흐름
  1. 최상위 댓글의 [답글]을 누르면 그 아래에 답글 입력창이 열린다.
  2. 내용을 쓰고 [등록]을 누르면 답글이 부모 댓글 아래에 추가되고 "답글을 등록했습니다." 알림을 보여 준다.
  3. [취소]를 누르면 입력창이 닫힌다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 내용 조건 위반 | F-15와 같음 |
  | 답글에 답글을 달려고 함 | 거절. 답글은 **1단계까지만** 허용 |
  | 부모 댓글이 삭제됨 | 거절 |
  | 부모 댓글이 다른 과제의 댓글 | 거절 |

### F-17. 댓글·답글 수정

- 사용할 수 있는 사람: 작성자 본인
- 정상 흐름
  1. 내 댓글의 [수정]을 누르면 그 자리에 기존 내용이 채워진 입력창이 열린다.
  2. 내용을 고치고 [수정 완료]를 누르면 "수정됨" 표시와 함께 "댓글을 수정했습니다." 알림을 보여 준다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 내용 조건 위반 | F-15와 같음 |
  | 작성자가 아님 | 수정 거절 |
  | 없거나 삭제된 댓글 | 수정 거절 |

### F-18. 댓글·답글 삭제

- 사용할 수 있는 사람: 작성자 본인
- 정상 흐름
  1. 내 댓글의 [삭제]를 누른다.
  2. "삭제한 내용은 복구할 수 없습니다. 답글이 있다면 답글은 유지됩니다." 확인 창에서 [삭제]를 누른다.
  3. 댓글 내용을 지우고 삭제 시각을 기록한다(소프트 삭제). "댓글을 삭제했습니다." 알림을 보여 준다.
  4. 화면 표시는 F-10의 댓글 표시 규칙을 따른다.
- 실패·예외 흐름

  | 상황 | 처리 |
  | --- | --- |
  | 작성자가 아님 | 삭제 거절 |
  | 없거나 이미 삭제된 댓글 | 삭제 거절 |

- 비고: 댓글은 지워도 행을 남기는 이유는, 답글이 달린 댓글을 완전히 지우면 답글의 부모가 사라져 대화 흐름이 끊기기 때문이다.

### F-19. 사이드바 요약

- 사용할 수 있는 사람: 누구나 (비회원 안내 화면에서도 사이드바가 보인다)
- 정상 흐름: 모든 화면의 사이드바에 활동 회원 수와 전체 과제 수를 보여 준다.

## 5. 결정 사항과 제안

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 서버 재검사 | 화면 검사와 별개로 서버에서 로그인·권한·입력을 모두 검사한다. | API는 화면을 거치지 않고도 호출할 수 있다. 브라우저 기본 문구("이 입력란을 작성하세요")는 서비스 문구가 아니다. |
| 제목·내용 오류 문구 | 와이어프레임은 한 문장으로 묶었지만 항목별로 나눈다. | 사용자가 어느 칸을 고쳐야 하는지 바로 알 수 있다. |
| 이메일 형식 검사 | 서버에서도 검사한다. | 와이어프레임은 브라우저의 `type="email"`에만 맡긴다. |
| 비밀번호 확인 | 화면에서만 검사하고 서버로 보내지 않는다. | 같은 값을 두 번 보내는 것은 입력 실수를 막기 위한 화면의 역할이다. |
| 비밀번호 저장 | BCrypt 해시로 저장한다. ERD에 `password_hash` 컬럼을 추가한다. | 예시 ERD에 비밀번호 컬럼이 없다. 평문 저장은 유출 시 위험하다. |
| 탈퇴 시 닉네임 | 와이어프레임처럼 "탈퇴한 회원"이라는 글자로 덮어쓰지 않고 NULL로 비운다. 표시는 서버 응답에서 처리한다. | 닉네임에 UNIQUE가 걸려 있어 두 번째 탈퇴자부터 충돌한다. |
| 첨부 오류 처리 | 화면은 그 파일만 거절, 서버는 요청 전체를 거절한다. | 서버에는 과제와 파일이 한 번에 도착한다. |
| 없는 페이지 | 오류 대신 빈 목록과 전체 페이지 수를 준다. | 화면에서 마지막 페이지로 옮겨 줄 수 있다. 와이어프레임은 마지막 페이지를 보여 준다. |
| 다운로드 권한 | 로그인한 회원만 내려받을 수 있다. | 비회원은 과제 화면 자체를 볼 수 없다. |
| "탈퇴한 회원" 작성자 검색 | **모임에서 정하기** | 와이어프레임에서는 검색되지만, DB에는 닉네임이 NULL이라 같은 동작을 하려면 서버에서 따로 처리해야 한다. |
| 인증 방식 | **모임에서 정하기** (API 명세서는 세션 기준으로 작성) | 와이어프레임에 로그아웃 버튼이 있어서 서버에서 바로 끊을 수 있는 세션 방식이 단순하다. 토큰(JWT)을 쓸지 함께 정한다. |
| (제안) 지각 제출 | 범위에서 제외하고 의견을 묻는다. | 와이어프레임에 마감일 개념이 없다. 넣으려면 마감일 입력 화면, ERD 컬럼, 관련 API가 더 필요하다. |
